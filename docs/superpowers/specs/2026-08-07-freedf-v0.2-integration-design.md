# FreeDF v0.2 — Integration Release: Design

Date: 2026-08-07
Status: approved
Scope: expose existing functionality cleanly. No new PDF capability.

## Goal

The engine already does the work. This release makes every implemented feature
reachable through every public surface, under a versioned contract, with a
defined session lifecycle, discoverable capabilities, stable artifacts, an
acceptance test suite, and documented deployment models.

Explicitly out of scope: text editing, content stream parser, font model,
annotations, forms, optimization, signatures, watermarks.

## Baseline

Surveyed at commit `c18b757` (branch `feat/ocr-text-layer`).

Three surfaces already route through one dispatcher: the Python façade
(`PdfEngine`), the JSONL agent CLI (`cli/agent.py`), and the loopback HTTP
service (`service/http.py`) all reach `CommandDispatcher.dispatch`.

Seven gaps against the objectives:

1. `AddTextLayer` exists in `api/models.py` but `parse_operation` has no
   `add_text_layer` branch, so OCR is Python-only.
2. `API_VERSION = "v1"` exists with four schema files, but no compatibility
   policy and no schema for `add_text_layer`.
3. Sessions carry a bare `closed: bool`. Invalid transitions collapse into
   `SessionNotFoundError`.
4. `_command_capabilities` drops `sessionId`, so the per-document `read`
   capability the engine already computes is unreachable over JSON. No OCR
   language list.
5. `CommandDispatcher.artifacts` is an unbounded in-process `dict[str, bytes]`,
   render-only, never evicted, retrievable only over HTTP.
6. `test_contract_parity.py` is five tests against a stub renderer. No
   end-to-end acceptance workflow.
7. One `pyproject.toml` and two docs; no deployment-model documentation.

Environment note: Poppler 25.07.0 is installed. Tesseract is not. The test
design must survive that and must not stop verifying the OCR contract
because of it.

## 1. Contract: additive v1

`apiVersion` stays `"v1"`. Everything v0.2 adds is additive.

### Additions

- `COMMANDS` gains `"artifact"`.
- Operation kinds gain `"add_text_layer"`.
- `SCHEMA_NAMES` gains `"artifact-request"` and `"capabilities-response"`.
- `operation-request.json` gains the `add_text_layer` variant.

### Compatibility policy

New file `docs/contract-policy.md`. Within a major contract version we MAY add
commands, operation kinds, response fields, capability entries, and error
`details` keys. We MUST NOT remove or retype an existing field, change an error
`code`, or tighten validation on a payload that was previously accepted. Any of
those forces `v2`.

The policy states the input/output asymmetry explicitly:

```
Unknown response fields MUST be ignored by clients.
Unknown request fields remain rejected.
```

Strict input validation is preserved: `_reject_unknown` stays on every command
and every operation. Response growth is safe by contract, so clients that
ignore unknown response fields keep working across additive releases.

### Changelog

New file `docs/CONTRACT-CHANGELOG.md`, one entry per contract change, opening
with the v0.2 additions above and the one behaviour refinement from §3.

### Frozen surface manifest

`tests/contracts/golden/v1-surface.json` enumerates every command, operation
kind, error code, and capability key. A test asserts the live surface matches
it. Removing a public name fails loudly rather than silently shrinking the API.

## 2. OCR parity

`parse_operation` gains an `add_text_layer` branch:

```json
{
  "kind": "add_text_layer",
  "pageIds": ["page_..."],
  "language": "eng",
  "mode": "lstm",
  "dpi": 300,
  "minConfidence": 0.0
}
```

Optional fields default to the `AddTextLayer` dataclass defaults. Unknown
fields are rejected like every sibling operation. Validation errors surface as
`invalid_request` with `details.field`; recognition failures surface as the
existing `ocr_unavailable` / `ocr_error` codes with `details.feature`.

Parity for this operation is verified on a fake OCR backend so it runs
everywhere (see §6). Real Tesseract recognition is verified separately.

## 3. Session lifecycle

States: `OPEN` and `CLOSED`. No artificial ordering — rendering before
inspecting, saving twice, and editing after a save all remain legal, because
they always were and nothing about them is unsafe.

### Tombstones

`close()` retains a lightweight tombstone so a closed ID stays distinguishable
from an ID that never existed. The tombstone holds exactly:

```
session_id
state = CLOSED
closed_at
```

No document model, no reader, no cache directory, no password — those are
released at close as they are today. Tombstones live for the life of the
process.

### Errors

- Unknown ID → `session_not_found` (unchanged).
- Tombstoned ID → new `SessionStateError`, `code = "session_invalid_state"`,
  `details = {sessionId, state, attempted, allowed: [...]}`.

This is the release's one behaviour change and is recorded in the changelog. It
is an error-path refinement: a request that failed before still fails, with a
more specific code and an actionable `allowed` list.

### Surfacing

`allowedCommands[]` belongs to the capabilities response (§4), not to every
`inspect` result. `inspect` gains only `state`.

A tombstoned session cannot serve a capabilities request — `capabilities` with a
closed `sessionId` raises `session_invalid_state` like any other command. The
error's own `details.allowed` list is therefore the sole answer for a closed
session, and it contains exactly `["open"]`: nothing else can be done with that
ID. `allowedCommands[]` in the capabilities response covers `OPEN` sessions.

### Known limitation

`ThreadingHTTPServer` permits concurrent requests against one session. v0.2
does not add a BUSY state or locking. The contract documents single-writer-per-
session as the caller's responsibility.

## 4. Capability discovery

One command, `capabilities`, with an optional `sessionId`.

- Without a session: engine-level only — `preview`, `ocr`, `operations`,
  supported filters, save policy.
- With a session: adds a `document` block — `structuralEdit`, `textContent`,
  undecodable `filters`, per-operation availability for that document, plus
  `allowedCommands[]` for the session's lifecycle state.

### State vocabulary

Every capability entry is `{state, detail}` where `state` is exactly one of:

| state | meaning |
| --- | --- |
| `ready` | engine and document both permit the operation |
| `blocked` | the engine supports it; this document or session blocks it |
| `unavailable` | this installation cannot provide it right now (e.g. Tesseract missing) |
| `error` | the capability probe itself failed |

`blocked` and `unavailable` always carry a human-readable `detail`. Agents can
branch on `state` deterministically instead of discovering limits by failure.

### OCR languages

The `ocr` block gains `languages[]` and `modes[]`. This requires a new
`OcrEngine.languages()` method on the base contract, implemented in
`TesseractOcr` via `--list-langs`, cached per process alongside the existing
executable and legacy-mode probes. A missing binary yields
`{state: "unavailable", languages: [], detail: "..."}` and never raises — the
same discipline `ocr_capability` already follows.

### Caching

Machine probes cache per process; they describe the installation, not any
document. Document probes cache per session, mirroring the existing
`undecodable_survey` field.

## 5. Artifacts

An artifact is a descriptor over a storage reference, not a bag of bytes.

```
Artifact {
    artifact_id
    kind          # page_render | thumbnail | saved_document
    content_type
    byte_size
    sha256
    session_id
    storage       # MemoryArtifact | FileArtifact | CacheArtifact
    metadata      # kind-specific, e.g. {pageId, width, height}
}
```

Storage backends:

- `MemoryArtifact` — bytes held in process. Small, transient.
- `CacheArtifact` — a file under the session cache directory (rendered pages
  already land there via `RenderCache`).
- `FileArtifact` — a file the user committed to, outside the cache. A
  `saved_document` is this: the writer already produced the file, so the
  artifact references it. A large PDF is never re-read into RAM to become an
  artifact.

`ArtifactRegistry` is owned by `PdfEngine`, keyed by `artifact_id`, with each
entry bound to its `session_id`.

### Kinds

v0.2 emits `page_render`, `thumbnail`, and `saved_document`. The enum is
documented as extensible; `extracted_document` is deferred. Extraction remains
`extract_pages` followed by `save`, and the resulting file is a
`saved_document`. No new command.

### Commands

- `render` result gains `artifact` and keeps `imageBase64` (additive rule).
- `save` result gains `artifact` and keeps `path`.
- New `artifact` command: `{sessionId, artifactId}` returns the descriptor plus
  base64 `bytes`. Available on all three surfaces, closing the second parity
  gap — today only HTTP can fetch artifact bytes.
- HTTP keeps `GET /v1/artifacts/<id>` as a raw-bytes convenience, now reading
  the same registry.

### Ownership

Retrieval enforces session ownership: the requested `artifactId` must belong to
the `sessionId` in the request, and that session must be `OPEN`. An unguessable
ID is not treated as an authorization mechanism. A mismatch is
`invalid_request` with `details.field = "artifactId"` — it does not disclose
whether the artifact exists under another session.

### Cleanup

```
close session
├── remove registry descriptors for that session
├── remove temporary render/cache artifacts (MemoryArtifact, CacheArtifact)
└── NEVER delete committed saved outputs (FileArtifact)
```

A `saved_document` is a file the user asked for. Closing a session forgets the
descriptor; it does not touch the file.

## 6. Test suite

Split by what a tier actually needs, so a machine without Tesseract still
verifies the OCR *contract* and only skips the real *implementation*.

```
tests/contracts/            always run; fake renderer and fake OCR
tests/integration/          real parser and writer, no external binaries
tests/integration/real_poppler/     requires Poppler
tests/integration/real_tesseract/   requires Tesseract
```

### Contract parity — always runs

Transport and contract parity must never depend on an installed binary. A
`FakeOcr` backend is added beside the existing `StubRenderer` and injected via
the existing `PdfEngine(renderer=..., ocr=...)` seams. Every command, including
`add_text_layer` and `artifact`, is exercised through Python, JSONL, and HTTP.

Comparison is **normalized semantic**, not byte-identical. Generated values are
replaced with placeholders before comparing:

```json
{"requestId": "<normalized>", "sessionId": "<normalized>", "artifactId": "<normalized>"}
```

Structure and meaning must match across surfaces; legitimately surface-specific
or generated values must not force false failures.

### Acceptance workflow

The suite in `tests/integration/` runs the release's acceptance workflow across
all three surfaces:

```
open → inspect → capabilities → render → apply → render → OCR → save
     → reopen → verify → close
```

Verifies:

- the saved document reopens and parses (validity);
- the source file is byte-identical after save (immutable source);
- page identities are stable across the operation batch;
- geometry is as expected after rotate and crop;
- recognized text is present in the saved bytes (searchable text);
- the session cache directory is gone after close, and a committed
  `saved_document` still exists (correct cleanup).

The OCR leg runs against `FakeOcr` here and against real Tesseract in
`real_tesseract/`.

### Dependency-aware tiers

Markers `requires_preview` and `requires_ocr` skip the real-tool tiers when the
binary is absent. Independently of skipping, a capability test **always** runs
and asserts the report says `unavailable` with a reason when a dependency is
missing. An absent dependency is itself covered behaviour.

### Mechanics

`test_contract_parity.py` currently imports `StubRenderer` from
`test_engine.py`, which works only because pytest puts a flat `tests/` on
`sys.path`. Moving tests into subdirectories breaks that. Shared fakes and
fixtures move to `tests/support/`, added to `pythonpath` in `pyproject.toml`
alongside `src`. Markers are registered in `pyproject.toml` so an unknown
marker is an error, not a warning.

## 7. Packaging

New `docs/deployment.md` describing three supported models. It explains
trade-offs; it does not declare one canonical. Running the same core behind
three interchangeable surfaces is a feature of the design, not an accident to
be resolved.

| Model | Use when | Lifecycle | Failure modes |
| --- | --- | --- | --- |
| Python package | The caller is Python and wants typed models and in-process speed | Caller owns `PdfEngine`; sessions live as long as it does | Exceptions propagate as typed `PdfEngineError` subclasses |
| HTTP service | Multiple clients, or a non-Python caller that wants a socket | One process, one dispatcher; loopback by default, network needs `--allow-network` | HTTP status plus the same JSON error envelope |
| JSONL subprocess | An agent or tool that speaks stdin/stdout | One request per line, responses in order; process exit closes every session | Malformed lines answered with an `invalid_request` envelope, stream continues |

`pyproject.toml` console scripts and extras are verified against what the doc
claims, with a smoke test that both entry points import.

---

## Acceptance criteria

v0.2 is done when:

1. `add_text_layer` and `artifact` work identically through Python, JSONL, and
   HTTP, verified by parity tests that run without Tesseract or Poppler.
2. `docs/contract-policy.md` and `docs/CONTRACT-CHANGELOG.md` exist, and the
   frozen surface manifest test passes.
3. Closed sessions return `session_invalid_state`; unknown IDs return
   `session_not_found`; both are tested.
4. `capabilities` answers with and without a `sessionId`, reports OCR
   languages, and uses the four-state vocabulary exactly.
5. Artifacts are descriptors over storage; `saved_document` survives
   `close()`; retrieval enforces session ownership.
6. The acceptance workflow passes across all three surfaces, and the
   dependency-aware tiers skip cleanly while capability assertions still run.
7. `docs/deployment.md` describes all three models with trade-offs.

No new major PDF functionality is added.
